# Лабораторная работа №4: Классификация с применением Scikit-Learn

## Цель работы
Построить модель классификации для предсказания кредитного дефолта на основе данных Kaggle "Give Me Some Credit", сравнить различные алгоритмы и выбрать наилучший.

## Ход выполнения

### 1. Загрузка и анализ данных
- Датасет содержит 50000 наблюдений и 11 признаков
- Целевая переменная: `SeriousDlqin2yrs` (есть ли просрочка 90+ дней)
- Выявлен сильный дисбаланс классов: ~93% хороших заемщиков, ~7% дефолтных

### 2. Предобработка данных
- Заполнение пропусков средними значениями
- Масштабирование признаков для SVM и KNN
- Разделение на обучающую (50000) и тестовую (37500) выборки

### 3. Результаты обучения моделей

| Модель | Accuracy | ROC-AUC |
|--------|----------|---------|
| Logistic Regression | 0.9325 | 0.6618 |
| Random Forest | 0.9338 | 0.8414 |
| SVM | 0.9337 | 0.6610 |
| KNN | 0.9263 | 0.6730 |
| **Gradient Boosting** | **0.9357** | **0.8645** |

**Вывод:** Gradient Boosting показал наилучший результат (ROC-AUC = 0.8645)

### 4. Анализ современных алгоритмов классификации

На основе анализа Kaggle-соревнований и научных публикаций:

| Алгоритм | Особенности | Применение в скоринге |
|----------|-------------|----------------------|
| **LightGBM/XGBoost** | Градиентный бустинг, высокая скорость | Стандарт индустрии |
| **CatBoost** | Работа с категориальными признаками | Хорош для банковских данных |
| **Stacking Ensemble** | Комбинация нескольких моделей | Топ-решения на Kaggle |

### 5. Интеграция модели с веб-сервисом

**Пошаговый алгоритм деплоя модели:**

1. **Сохранение обученной модели** с помощью библиотеки `joblib` или `pickle`

2. **Создание API на FastAPI** с эндпоинтом `/predict`

3. **Предобработка входных данных** (масштабирование, заполнение пропусков)

4. **Возвращение предсказания** в формате JSON

5. **Контейнеризация с Docker** для воспроизводимости

6. **Деплой в облако** (AWS, GCP, Heroku)

## Выводы
- Градиентный бустинг — наиболее эффективный метод для кредитного скоринга
- ROC-AUC — более информативная метрика при работе с несбалансированными данными
- Для реального внедрения требуется дополнительная настройка порога классификации
